Export downloads a redacted copy of this plugin's configuration; provider secrets and account links are never included. Import merges an exported file into this instance, keeping the stored secret and account links of each unchanged provider. An import that gives an OpenID provider a different discovery endpoint or client id clears that provider's links and secret, as a repoint safety measure. Review a file before importing it over a live provider, and re-enter each provider's secret afterwards. Requires administrator privileges.

Off by default: the plugin never touches the server's login branding unless you opt in here. When on, a managed "Sign in with …" block with one button per enabled provider is spliced into the login page's branding disclaimer. The block is refreshed whenever this plugin's configuration is saved and at server start. When off, only that managed block is removed; any disclaimer content you wrote yourself is preserved either way. Each provider's editor below can hide its button or give it a custom label.

Off by default. When on, each login stores the session state a logout needs, and two logout surfaces become active. The RP-initiated OpenID logout route ends the linked Jellyfin session and can send the browser on to the provider's end-session endpoint. The inbound SAML LogoutRequest endpoint ends the Jellyfin session the request names. The OpenID route also accepts a one-time ticket from an authenticated call, so a client never puts an access token in the address. While off, both surfaces reject and no ticket is issued; local Jellyfin logout is unaffected. Set each OpenID provider's post-logout redirect URL in its editor below.
